# v0.1 — M1: Foundation & Bootstrap

> **Draft — not published.** Milestone closure marker for M1.
> A formal release tag will be cut later; this file accumulates notes
> for v0.1 as M1 lands.

## Summary

First end-to-end milestone for switchx. A user can install the binary,
complete a four-step bootstrap wizard, and reach a placeholder home
screen that confirms the application is connected to its Postgres
database. No domain features are implemented yet — this milestone
proves the operational spine.

## What's included

- **Repository scaffold** — hexagonal layout per @ADR-0003 with
  `internal/domain/`, `internal/app/`, `internal/storage/`,
  `internal/ui/tui/`, `migrations/`, and `cmd/switchx/`.
- **CI** — `go vet ./...`, `go test ./...`, and `golangci-lint run` on
  every pull request.
- **Config loader** — TOML at `$XDG_CONFIG_HOME/switchx/config.toml`
  (falling back to `~/.config/switchx/config.toml`). Refuses to start
  if the file mode is more permissive than `0600`.
- **Bootstrap wizard** — modal four-step UI (database, secret,
  identity, preferences) that runs on every launch where the config
  is missing or incomplete, and re-runs until the database connection
  validates.
- **Secret resolver** — Azure Key Vault via the `az` CLI. Single
  provider in M1; additional providers deferred.
- **Database layer** — `pgx/v5` with `pgxpool` (max 4 connections).
  Pool opened at startup, closed on `q` / Ctrl+C.
- **Migrations runner** — `golang-migrate` over an embedded migration
  set. Runs on every application start, idempotent. M1 ships with no
  schema; the first migration arrives in M2.
- **Placeholder home screen** — minimal Bubble Tea shell showing
  "Connected to {dbname}". Conforms to the @UI Patterns baseline
  (breadcrumb + hint bar) but exposes no functional keys beyond
  `q`, Ctrl+C, and `?`.
- **Startup decision tree** — distinguishes no-config (→ wizard),
  valid-config (→ home), and unreachable-DB (→ error screen with a
  retry path).

## Not included (deferred to M2+)

- Any domain entity (Client, Project, Assignment, Session, BacklogItem).
- Any real TUI view beyond the wizard, home, and error screen.
- Multi-secret-provider support (HashiCorp Vault, 1Password, etc.).
- An in-app config editor (the TOML file is hand-edited or
  re-generated via `switchx --edit`).
- Schema migrations (deferred to M2 with the first entity).
- Install tooling beyond `go install` (Homebrew formula, GitHub
  Releases binaries).

## Verification

- Manual: walk `docs/m1-smoke-test.md` on a clean Linux environment.
- Automated: `make smoke-integration` runs the end-to-end test
  (`TestM1E2E`) against a live local Postgres provisioned by
  `make dev-up`.

## Locked decisions

These were settled during M1 planning and remain in force unless
explicitly revisited:

- PostgreSQL minimum version: **16** (tested against 16 and 17).
- Migrations run on every launch, not only after wizard completion.
- The wizard re-runs until the database connection is validated.
- `internal/storage/postgres/migrations/` ships empty in v0.1.
