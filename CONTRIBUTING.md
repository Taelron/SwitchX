# Contributing to switchx

## Dev environment

The dev workflow runs the binary against a dev-local config at
`.local/dev-config/switchx/config.toml`, generated by `make dev-up`
from `.local/.env` + sensible defaults. The deployed `switchx` binary
(installed via `go install`) reads `~/.config/switchx/config.toml`
and is completely separate from the dev flow.

See the main `README.md` for the first-run setup (`cp .env.example`,
`make dev-up`, `make run`).

## env-var contract

These are the variables the `.local/dev-env/*.sh` scripts read.
Required values must be set; everything else uses the default
unless you override it (either in `.local/.env` or in your shell).

| Variable | Required? | Default | Set in |
|---|---|---|---|
| `AZURE_VAULT` | **yes** — fail-fast if unset | (none) | `.local/.env` or shell |
| `AZURE_SUBSCRIPTION` | no | `az account show --query name -o tsv` | `.local/.env` or shell |
| `KV_USER_REF` | no | `SWITCHX-DB-USER` (ADR-0005 operator contract) | `.local/.env` or shell |
| `KV_PASSWORD_REF` | no | `SWITCHX-DB-PASSWORD` (ADR-0005 operator contract) | `.local/.env` or shell |
| `PG_HOST` | no | `localhost` | `.local/.env` or shell |
| `PG_PORT` | no | `5432` | `.local/.env` or shell |
| `PG_DB` | no | `switchx` | `.local/.env` or shell |
| `PG_USER` | no | `switchx_user` | `.local/.env` or shell |
| `PG_SSLMODE` | no | `disable` | `.local/.env` or shell |
| `PG_SERVICE` | no | `postgresql` (systemd unit) | `.local/.env` or shell |
| `DEV_XDG` | no | `.local/dev-config` | `Makefile` |

`DEV_XDG` is the only one whose default lives in the `Makefile` —
because the `Makefile` consumes it directly (`XDG_CONFIG_HOME=$(DEV_XDG)`
on five targets). Every other variable is consumed by the shell scripts,
so the default lives in the script (`${VAR:-default}`).

The minimal `.local/.env` for a contributor working against the
standard switchx setup is one line:

```
AZURE_VAULT=<your dev Key Vault name>
```

Add overrides as needed; commented-out templates for every variable
live in `.local/.env.example`.

## How values flow

1. **`.local/.env`** — sourced by the dev scripts at the top of each
   script that needs values. Gitignored.
2. **Defaults in scripts** — `${VAR:-default}` resolves to the default
   when `.local/.env` doesn't set the variable.
3. **`make dev-up`** — reads the resolved values, fetches the DB
   password from Azure KV, provisions the local Postgres role +
   database, and writes the dev config to
   `.local/dev-config/switchx/config.toml`.
4. **`make run`** (and `make bootstrap-test-*` / `make startup-test-*`)
   — sets `XDG_CONFIG_HOME=.local/dev-config` so the binary reads the
   dev config, never `~/.config/switchx/`.

## Verification

The one-shot regression target:

```
make regression       # build + lint + unit + naming + env-failfast + PG integration + E2E
```

This runs every automated check in order, fast-first. Use it before
pushing or after any non-trivial change. Requires the local PG running
(via `make dev-up`) and `.local/.env` populated with `AZURE_VAULT`.

The individual targets, if you want to run a subset:

```
make verify           # build + vet + lint + unit tests (fast, no PG/KV needed)
make verify-local-env # naming-leak + env fail-fast (fast, no PG/KV needed)
make pg-integration   # gated PG integration tests against the local DB
make smoke-integration # TestM1E2E end-to-end against the local DB
```

The `verify-naming-leak` check enforces that internal names that leak
operational topology (real vault names, subscription names) do not
appear in tracked content. Add patterns to
`.local/dev-env/verify-naming-leak.sh` as new internal names enter
the project.

## Direnv

For project-scoped env vars without polluting `.bashrc`, [direnv](https://direnv.net/)
is a good fit. Create `.envrc` (gitignored) with:

```
export AZURE_VAULT=<your dev Key Vault name>
```

Then `direnv allow` once. `make dev-up` and friends pick up the
variable automatically inside the repo directory.
